# study-timer · 功能发散存档（2026-09-12）

> 来源：统计"应用"视图上线后的新一轮思维发散。本文档只做**存档与排序**，不改变实施约定；
> 立项前先过一遍 `tool-drawer-roadmap.md` 的「收录原则」与「落选记录」——自由番茄钟、应用屏蔽、

> 标注说明：【已实施】本批落地；【纯渲染端】不动主进程；【壳层】需动主进程、按约定单独评审。

## 背景：新增的数据资产

前台应用采集已上线（`app-usage-tracker.js` + `app-usage-model.js`）：按天记录"何时前台在用哪个应用"
（息屏/锁屏/离开不记录），归属（学习/短休/大休·其他）在渲染端按当天作息块动态切分。所有
appUsage 衍生功能的领域逻辑都应继续落在 `app-usage-model.js` 纯函数 + `tests/` 里。

## 二、作息核心循环

| 功能 | 状态 | 成本 | 说明 |
|---|---|---|---|
| 科目/项目标签 | 候选 | 纯渲染端 | 把时间块"做的事"（act）升级为标签体系；统计页加科目分布/趋势。主要工作量在标签管理 UI |
| 周/月目标 | 候选 | 纯渲染端 | 现在只有每日 `dailyMin`；配合阶梯休息券已有的周概念 |
| 块长 × 完成率分析 | 候选 | 纯渲染端 | 洞察页新卡：不同块长的完成率对比，给"40 分钟是否太长"一个数据答案 |
| 晨间意图 | 候选 | 纯渲染端 | 打卡"开始今天"时记一句"今天最重要的一件事"（存 checkin），晚间总结回看 |
| 复盘预填（非 AI） | 候选 | 纯渲染端 | 总结页"从今日数据预填"：专注分钟/完成/跳过原因/Top 应用拼成草稿。纯模板拼接，与已落选的"AI 总结"划清界限 |

## 四、排序建议

1. **短平快**：导出补 appUsage（半小时级）→ 托盘/面板显示当前应用（顺手壳层项）。
2. **观察后再定**：白名单标注与轻守卫——让真实数据积累两周，看分心分布是否有守卫的价值。
3. **体验组合拳**：晨间意图 + 复盘预填（一对做，串起门禁→手记闭环）。
4. **大数据卡**：科目标签、块长分析各自独立立项，过收录原则评审后排期。
